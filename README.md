## 延迟表现：到国内 230–250ms，到欧洲是主场

RackNerd 纽约节点到中国大陆，单程延迟普遍落在 230–250ms 区间。数据包要先穿越整个北美大陆，再走跨太平洋海缆；联通和电信多走 Cogent 线路，晚高峰（北京时间 20 点之后）偶尔有波动。这是东海岸机房的共同天花板，路由结构决定的，哪家都躲不掉。用户主要在国内的话，西海岸天生更合适。

去欧洲就是另一幅图景：跨大西洋海缆从东海岸出发，布法罗到英国、德国的路由明显短于西海岸。参考纽约都会区 VPS 的典型往返数据：都会区内部约 2ms，到弗吉尼亚 Ashburn 约 8ms，多伦多约 14ms，芝加哥约 22ms，达拉斯约 38ms，迈阿密约 40ms，洛杉矶约 70ms，伦敦约 78ms，法兰克福约 88ms。这组是公开网络的参考值，布法罗离纽约都会区还有几百公里，实际会再高几毫秒，自己的路由自己测。

还有一个容易被忽略的账：延迟在协议层会翻倍。新建一条 HTTPS 连接至少要 3 个来回（TCP 握手、TLS 握手、发请求拿首字节），按到伦敦 78ms 的往返算，浏览器拿到第一个字节要等约 234ms。这正是东海岸服务器服务欧洲用户依然可接受、而西海岸做不到的原因。

**选法很简单**：用户集中在波士顿—华盛顿走廊或欧洲，纽约合适；用户遍布全美或主要在国内，中部或西海岸更优。同一家也有洛杉矶、达拉斯等节点，下单时可以切换。
